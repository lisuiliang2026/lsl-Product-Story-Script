# lsl-Product-Story-Script　产品广告故事设计

版本：1.1.0（2026-11-11）
维护者：本 Skill 所在 Claude 账号的所有者。改规则、升版本都要维护者认可。

这份说明是给人看的。Claude 实际执行的内容在 `SKILL.md`。

## 一、这是什么

一条产品视频广告，在写分镜之前要做的事，都归这个 Skill：

1. 找出唯一的核心价值，出创意。
2. 把选定的创意写成完整的故事设计。
3. 做声音设计。
4. 整理成交给导演环节的资料。

它不写镜头表和视频提示词，那是故事确认之后导演环节（director-video-prompt）的事。它也不写单张图片的资产提示词。

## 二、怎么触发

不用点名，照平时的说法提需求就行。下面这些说法都会用到它：

| 你说 | 它会做 |
|---|---|
| 「先给我创意再细化」「给我十条创意」 | 只出创意，每条几行 |
| 「细化」「全部细化」「做文案剧本」 | 写文字故事稿，不写分镜 |
| 「继续调整」「还要调整」「表现不好」「不够饱满」「不够活」「喧宾夺主」 | 先自己诊断问题，再多方面一起改 |
| 「进入分镜」「写提示词」「交给导演」 | 整理交接资料，转到导演环节 |

## 三、它怎么工作

每一步交一份东西，等你确认再做下一步。

| 步骤 | 交给你的东西 | 等你确认什么 |
|---|---|---|
| 0 接任务 | 产品部位表；这次任务碰到的已知不足和打算怎么做 | 和第 1 步一起看 |
| 1 创意 | 核心价值；你要的条数的创意；推荐先做哪条 | 选哪些往下做，先做哪条当标杆 |
| 2 故事设计 | 《故事设计》：人物、群演、关系、产品主线、逐拍故事、反转和升华、细节织入、活化和特效、各项检查表 | 故事通过 |
| 3 声音设计 | 《声音设计》：逐拍的环境音、音效、人声；需要配乐时另有《配乐需求》 | 声音通过 |
| 4 交接 | 给导演环节的交接资料 | 到此结束 |
| 生成之后 | 质检和播放数据复盘的结论 | 是否铺开到其余几条 |

被打回时，它会先列「你指出的问题、上一版怎么写的、这一版怎么改」的对照表，再从人物、关系、情节、产品、活化、反转、升华七个方面一起改。

## 四、包里有什么

| 文件 | 内容 |
|---|---|
| `SKILL.md` | 正文：触发说明、工作流程、你的八条基线要求和 29 条规则（每条带原因）、13 组正反例、交付前自检清单、七条已知不足、版本记录 |
| `references/candidates.md` | 9 条候选做法。只出现过一次，还不算规则，用到时会告诉你「这是候选做法」 |
| `README.md` | 本说明 |

## 五、怎么安装

1. 在 Claude 桌面版里上传 `lsl-product-story-script_v1.1.0.zip`，方式和上传其他 Skill 压缩包相同。
2. 想核对文件有没有损坏：在终端里对 zip 运行 `shasum -a 256`，结果应当和同名的 `.sha256` 文件里的那串字符一致。
3. 新开一个对话，说一句「给这个产品先出创意再细化」，看它有没有被调用。也可以直接问「你现在用的是哪个 skill、哪个版本」。

## 六、和另外两个 Skill 的关系

- **director-video-prompt**：本 Skill 的产出是它的输入。写故事的阶段不调用它；你说进入分镜之后，它是参考和桥梁。你也可能让 Claude 直接按导演思路写视频提示词，那时同样以交接资料为准。
- **lira-image-prompts**：分工还没有定。本 Skill 的故事设计里要写主要人物的设定图提示词，这部分是由本 Skill 直接写，还是转给 Lira，需要维护者决定。

## 七、怎么维护和升级

什么时候升级：

- 标杆视频做完质检、复盘播放数据之后，把结论写回去。
- 实际项目里碰到 `SKILL.md` 第六节的某条不足，对接出维护者认可的做法之后。
- 某条候选做法再出现一次，并且维护者认可之后。

怎么升级：

1. 先把要改的内容列给维护者看，认可后再改。项目里碰到的新做法不直接写进 Skill。
2. 改源文件夹 `标准/lsl-product-story-script/` 里的文件。
3. 同步四处：`SKILL.md` 标题里的版本号、第七节的版本记录、第六节里对应不足的状态、本说明开头的版本行。
4. 打包成 `lsl-product-story-script_v<版本>.zip`，连同 `.sha256` 放进 `标准/`，旧版本的 zip 留着备用。
5. 重新上传安装。要退回旧版本时，重新上传旧版本的 zip。

版本号的规则和 lira-image-prompts 相同：并入新规则升次版本，只改措辞升修订号，整体重写升主版本。

只属于某个项目的内容不进 Skill，写在那个项目自己的项目备注里。

## 八、目前的限制

- 全部规则来自一个项目：2026 年 11 月的连财九鱼卫衣广告。
- 规则只在纸面上通过。按它写出来的故事还没有生成过视频，也没有播放数据。
- 还没有在新对话里测过它会不会被正确调用。
- 七条已知不足，详见 `SKILL.md` 第六节：
  1. 样本只有一个。
  2. 只保证纸面通过，不保证生成效果。
  3. 内容装不装得下一条片子，没有办法判断。
  4. 「高级」和「特效做足」没有通过的例子。
  5. 创意这一步最薄。
  6. 小场面没有例子。
  7. 和导演环节的交接没有试过。

按规则 29，Claude 在实际项目里碰到这些问题时会主动提出来，和你对接出做法。
